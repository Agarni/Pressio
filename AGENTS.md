# AGENTS.md

## What this is

Pressio is a cross-platform blood-pressure tracking app: Avalonia UI + .NET 10 + C# + ReactiveUI + SQLite. The product spec is `PRD.md` (in Portuguese) — read it before changing product behavior.

## Project layout & solution format

- Solution file is `Pressio.slnx` (the new XML `.slnx` format, **not** classic `.sln`). It is valid for `dotnet` CLI, but may not open in older tooling.
- All real code (views, viewmodels, models, services, styling) lives in the `Pressio/` project (`net10.0`). The other projects are thin launch hosts that only reference `Pressio`:
  - `Pressio.Desktop` — `Program.cs`, the main local-dev entry. `dotnet run --project Pressio.Desktop`.
  - `Pressio.Android`, `Pressio.iOS`, `Pressio.Browser` — platform hosts; require the respective .NET workloads (not installed by default on a dev machine).
- UI text and identifiers are in **Portuguese** (e.g. `"Registrar pressão"`, `"Claro"/"Escuro"`, `"Índigo"`). Keep new strings and values in Portuguese to match.

## Commands

```sh
dotnet build Pressio.Desktop/Pressio.Desktop.csproj   # fast core check
dotnet run --project Pressio.Desktop                   # run the desktop app
dotnet build                                           # whole solution
dotnet test Pressio.Tests/Pressio.Tests.csproj         # unit tests (parser, repositórios, filtros, lembretes, dashboard, PDF)
```

```sh
bash scripts/package-macos.sh osx-arm64   # monta Pressio.app (ícone/Info.plist) e abre
bash scripts/run-android.sh               # build + install + abre o app no emulador/dispositivo via adb
bash scripts/build-ios-altstore.sh        # .ipa SEM assinatura p/ instalar no iPhone via AltStore
bash scripts/deploy-ios-device.sh         # build + install + launch no iPhone físico (provisioning + assinatura)
```

**Teste de device iOS:** para instalar sem passar pela App Store, rode `bash scripts/build-ios-altstore.sh` (builds `Pressio.iOS` em `Release/ios-arm64` com codesign desabilitado) e envie o `.ipa` ao **AltStore** — o AltServer assina com seu Apple ID gratuito (validade ~7 dias; AltStore renova com o Mac+AltServer ligados). O projeto iOS só usa notificações locais (`UNUserNotificationCenter`), então a assinatura free funciona. Para **TestFlight/Ad-Hoc** (conta paga), aponte `CodesignKey`/`ProvisioningProfile` no `Pressio.iOS.csproj`.

**Deploy direto no iPhone (Xcode/devicectl):** `bash scripts/deploy-ios-device.sh` compila, instala e abre. Pré-requisitos (conta gratuita): adicionar o Apple ID no Xcode (gera o certificado "Apple Development"), ativar o **Modo de desenvolvedor** no iPhone e criar o provisioning profile com um projeto iOS descartável no Xcode (bundle id `agarnidev.Pressio`). **Atenção:** o Xcode guarda os `.mobileprovision` em `~/Library/Developer/Xcode/UserData/Provisioning Profiles/`, mas o .NET iOS **só procura em `~/Library/MobileDevice/Provisioning Profiles/`** — copie o profile do seu bundle id para lá (o script já faz isso).

## Package management

Versions are centralized in `Directory.Packages.props` (`ManagePackageVersionsCentrally=true`). **Never** add a `Version` directly in a `.csproj`; add it to `Directory.Packages.props` instead.

The Avalonia packages (Avalonia, Themes.Fluent, Fonts.Inter, Desktop, iOS, Browser, Android) **must all share the same version** — the file has a comment to keep them in sync. When bumping, bump them together. ReactiveUI.Avalonia, Microsoft.Data.Sqlite, SkiaSharp, and PDFsharp are versioned separately.

`SkiaSharp` (same version Avalonia uses, 3.119.4) is a direct reference in `Pressio` — used by **Avalonia rendering**, **not PDF anymore**. PDF generation lives in `Pressio/Services/PdfReportService.cs` using **PDFsharp** (`PDFsharp` 6.2.4, MIT, 100% managed — no native, works on desktop/iOS/Android) + the **Inter font** embedded as `Pressio.Assets.Fonts.Inter.ttf` (SIL OFL) via an `IFontResolver` (`InterResolver`) — PDFsharp requires a font resolver outside Windows. The native Skia (for rendering) comes from `Avalonia.Desktop`/`Avalonia.iOS`/`Avalonia.Android` at runtime.

`SQLitePCLRaw.bundle_e_sqlite3` is pinned at `2.1.13` (via `Directory.Packages.props`) to suppress the `NU1903` advisory on `lib.e_sqlite3 2.1.11` — keep it above 2.1.11.

## Build/CI gotchas

- Android: o `.NET for Android` exige **JDK 17+** (o `manifestmerger` é compilado para Java 17). O `Pressio.Android.csproj` define `JavaSdkDirectory` para o JDK 17 do sistema quando presente; caso contrário o SDK decide. **Precisa estar no `.csproj`** (não em `Directory.Build.props`) porque o Rider compila via um projeto temporário em `/var/folders`, que não importa o `Directory.Build.props` da raiz. Se o build Android falhar com `UnsupportedClassVersionError`, o JDK em uso é Java 11 — aponte `JavaSdkDirectory`/`JAVA_HOME` para um JDK 17. **Atenção:** depois de um build antigo (com JDK 11), o `obj` pode guardar a resolução anterior; rode `dotnet clean` + rebuild antes de instalar no emulador/dispositivo.
- iOS Debug uses `<UseInterpreter>true</UseInterpreter>` to avoid premature AOT loading; **Release also uses `<UseInterpreter>true</UseInterpreter>`** (verified stable). Keeping AOT in Release crashed on-device with `Failed to load AOT module 'ReactiveUI.Avalonia' ... out of date` / `System.InvalidProgramException` in `FinishedLaunching` — caused by **stale/corrupt AOT cache** in `obj`/`bin` that `dotnet clean` does NOT clear. **If you ever switch to AOT for Release**: (a) keep `MtouchLink=SdkOnly` + `MtouchNoSymbolStrip` + `MtouchExtraArgs=--interp`, and (b) after any code change run `rm -rf Pressio.iOS/obj Pressio.iOS/bin Pressio/obj Pressio/bin` + rebuild (or the AOT modules go stale and the app crashes at launch). `scripts/deploy-ios-device.sh` defaults to **`CONFIG=Release`**; use `CONFIG=Debug` to debug. Don't remove these settings without reason.
- **iOS app icon:** supplied via `Pressio.iOS/Info.plist` `CFBundleIcons`/`CFBundleIconFiles` + PNGs in `Pressio.iOS/Resources/AppIcon-*.png`. Do **not** rely on an `Assets.xcassets`/`AppIcon` asset catalog — the .NET/iOS toolchain here does **not** compile it into an `Assets.car` (its `actool/bundle/` stays empty). Icon/`Info.plist` changes need a **clean build** (`dotnet clean`) + reinstall, because incremental builds may not re-merge the `Info.plist`.

## Persistence

- SQLite via raw `Microsoft.Data.Sqlite` (no EF Core/Dapper, despite what `PRD.md` suggests).
- DB file: `%LocalAppData%\Pressio\pressio.db` (`PressioDatabase.Path`). Dates are stored as ISO-8601 strings; UTC on write, `.ToLocalTime()` on read.
- Backup/Restore (Settings → Dados): backup uses `VACUUM INTO` to a user-chosen `.db`; restore copies the chosen file over the DB path and reloads patients/measurements/reminders/settings. Repositories take an optional `dbPath` (used by tests).
- Both `MeasurementRepository` and `SettingsRepository` open the same DB file, each computing its own connection string.
- `ReminderRepository` also opens the same DB (table `Reminders (Id, Time TEXT, Days INTEGER, Enabled INTEGER, Note TEXT)`); `ReminderTime` is a `TimeSpan` stored as `HH:mm:ss`, days are a `[Flags] ReminderDays` mask.
- OS notifications are wired via `Pressio.Services.INotificationService`/`Notifications.Service` (set at host startup: `Program.cs` → `DesktopNotificationService`; `Application.cs` → `AndroidNotificationService`; `Main.cs` → `IosNotificationService`). `MainViewModel` schedules/cancels on reminder changes and reschedules enabled ones on start; **o `SaveReminder` só agenda se habilitado** (senão cancela o alarme). Desktop uses `osascript`/`notify-send`/`msg`; Android uses AlarmManager + NotificationChannel; iOS uses `UNUserNotificationCenter` (authorization requested lazily). In-app reminders still poll every 20s (`CheckDueReminders`) and show an overlay as a fallback. `INotificationService.SupportsScheduledNotifications` is **true on iOS/Android, false on desktop**: the `ShowNowAsync` fallback only runs where the OS does NOT schedule real notifications. **Device/emulator validation is required; on macOS notifications need a bundled `.app`.** Android `PendingIntent`s must use `PendingIntentFlags.Immutable` (targeting SDK 31+ crashes otherwise). **Android (13+):** é preciso pedir `POST_NOTIFICATIONS` **em runtime** (senão a notificação é bloqueada silenciosamente — o `MainActivity.OnCreate` já pede). O alarme usa **`setExactAndAllowWhileIdle`** (o `setAndAllowWhileIdle` era inexato e adiava ~1h — parecia "não notificar" com o app aberto); manifesto com `SCHEDULE_EXACT_ALARM`. A notificação tem `contentIntent` que **abre o app** ao tocar. **Notificação de app em primeiro plano é suprimida pelo Android** — para ver o alarme, o app precisa estar em segundo plano/ fechado (o overlay in-app cobre o app aberto).
- `MeasurementRepository.Initialize()` creates tables with `CREATE TABLE IF NOT EXISTS` plus a hand-rolled migration that checks `PRAGMA table_info` before `ALTER TABLE`. If you add a column, follow this same pattern (the existing checks detect `PatientId`, `Context`, `HeartRate`, `AtRest`, `Arm`, `Position`; each is added with an explicit `ALTER TABLE` when missing). **The app no longer auto-creates a "Meu perfil" default user** (removed after cloud sync — with multi-user, profiles come from the account or are created by the user; the dashboard handles the empty state). Tests create patients explicitly.
- **Sync:** `Patients`/`BloodPressureMeasurements`/`Reminders` carry `SyncId` (GUID) + `UpdatedAtUtc` + `Deleted` (tombstone), and `Measurements` also `PatientSyncId` — added/backfilled by the same `PRAGMA` migration. New rows get a fresh GUID. Reads filter `Deleted=0`/`GetAll`; `Delete*` **soft-delete** (set `Deleted=1`) so deletions propagate via sync. Snapshot DTOs live in `Pressio/Models/Sync/SyncModels.cs`, serialized by `SyncStore` (`pressio-sync.json`, camelCase + string enums). `SyncService` builds the local snapshot, **merges** remote+local (LWW by `UpdatedAt`, tie→local) and **applies** the result (upsert by `SyncId` + tombstones); `ExportToFile`/`ImportFromFile` cover the manual file flow. After each sync `SyncService.CompactTombstones(30)` removes tombstones older than 30 days (already propagated) so the DB/snapshot doesn't grow forever. Design: `docs/SYNC.md`.
- `BloodPressureMeasurement` stores a `[Flags] MeasurementContext` (stress, pain, fever, exercise, caffeine, alcohol, smoking, poor sleep, missed medication, diet, symptoms, other) as an `INTEGER` bitmask in the `Context` column. `MeasurementContextInfo` maps values to Portuguese labels (`Describe`/`AllContexts`); the measurement form renders toggle chips from `ContextOption` (`MainViewModel.ContextOptions`). It also stores optional `HeartRate` (nullable int), `AtRest` (bool), `Arm` and `Position` (enums stored as TEXT).
- The measurement display format (`13/8` vs `130/80`) is a persisted setting (`MeasurementDisplayFormat`) applied via the static `BloodPressureMeasurement.UseShorthandFormat`. **All** pressure displays (measurement rows, last reading, averages, medication summaries, chart labels, CSV) go through `BloodPressureMeasurement.Format`/`DisplayValue` so they stay consistent; change the setting in `SaveSettingsCommand` and it reloads measurements to refresh everything.
- `SettingsRepository` stores a simple key/value `Settings (Key TEXT PRIMARY KEY, Value TEXT)` table (used for theme + primary color via `SaveAppearance`). Appearance/primary color are loaded in `MainViewModel.LoadAppSettings()`, applied via `App.ApplyAppearance`, and applied+persisted **only** on confirming the Settings dialog (`SaveSettingsCommand`). Selecting a theme or a color swatch does NOT change the app before that (no live global preview); the selected color is indicated by a check inside the swatch via the `ColorMatchConverter`.
- Reusable looks live in `App.axaml`: button style classes (`primary-button`, `secondary-button`, `danger-button`, `icon-button`, `color-swatch`, `toggle-chip`) plus `ControlTheme`s like `PressioPrimaryButton`/`PressioColorSwatch`/`PressioIconButton`/`PressioToggleChip`. Dialogs and cards should use the `Pressio*` `DynamicResource` brushes (surface/text/muted/primary/border/banner) so they adapt to light/dark — avoid hardcoded hex for surfaces/text.
- Deletes of patients and measurements are gated behind a confirmation overlay driven by `MainViewModel` (`ConfirmDeleteCommand`/`CancelDeleteCommand`, `IsConfirmDialogVisible`).
- CSV/PDF export lets the user pick where to save via a native "Save as" dialog: `MainViewModel.ExportFileInteraction` (ReactiveUI `Interaction`) is handled in `MainView.axaml.cs` with `Avalonia.Platform.Storage` (`FilePickerSaveOptions`). The last used directory is persisted (`LastExportDirectory` in `SettingsRepository`) and reused as the start location. The report obeys `ReportPeriod` (Todo/Últimos 7/30 dias/Período personalizado com intervalo), prints the exact period range in the PDF header, and is capped at the 30 most recent records (note de truncamento). Depois de exportar, o app pergunta se abre (`ConfirmOpenInteraction`). **Escrita do arquivo por plataforma:** `StorageWriter.Service` (`Pressio/Services/StorageWriter.cs`) grava bytes no arquivo escolhido — no Android via `ContentResolver` (`AndroidStorageWriter`, SAF `openOutputStream`, porque o storage do Avalonia no Android **não suporta `OpenWriteAsync`** — dá "Specified method is not supported"); no iOS/desktop via `file.OpenWriteAsync()`. **O PDF é gerado por `PdfReportService` com PDFsharp (não mais SkiaSharp)** — o Skia `SKDocument.CreatePdf` crasha nativo no Android (SIGSEGV em `libSkiaSharp.so`), então foi migrado.
- **Sync UI (Configurações → Sincronização):** escolher pasta via `FolderPickerInteraction` (handled in `MainView.axaml.cs` com `FolderPickerOpenOptions`) + "Sincronizar agora" (`Settings.SyncRequested` → `MainViewModel.SyncNow`), que faz `SyncService.ImportFromFile(pasta/pressio-sync.json)` (merge + apply + regrava o arquivo). O caminho fica em `LastSyncDirectory` (`SettingsRepository`).
- **Sync na nuvem (Supabase):** `MainViewModel` usa `SupabaseClient` (auth por e-mail+senha via `/auth/v1/*`; snapshot via PostgREST `POST/GET /rest/v1/pressio_sync` por `user_id`, upsert com `Prefer: resolution=merge-duplicates`). A URL e a **anon key** (`SettingsRepository.Default*`) ficam embutidas no app — OK porque o **RLS** protege os dados por usuário (`auth.uid() = user_id`); **NUNCA** coloque a `service_role` aqui. O usuário só faz login (e-mail+senha com confirmação) em Configurações → Sincronização. `SyncNow` busca o snapshot do usuário, faz `ApplyRemote` (merge LWW) e grava de volta. `SyncCloudAsync` mostra um **aviso de sincronização** ao abrir ("Sincronizando dados com a nuvem…") — sem mensagem de sucesso, apenas o **erro** em caso de falha (`SyncNotifier`/`SyncNotifierIsError` no topo da `MainView`). O sync é automático no startup e **periódico a cada 2 min**; após login faz um sync. O fluxo de sync por **pasta** foi deixado de lado (não funciona no iOS) e a UI correspondente foi removida.
- **Apple Health (iOS):** `IosHealthExportService` (HealthKit) via `HealthExport.Service` (holder em `Pressio/Services/HealthExportService.cs`, vazio no desktop/Android). Grava uma `HKCorrelation` de pressão (sistólica/diastólica em mmHg) + `HKQuantitySample` de FC no app Saúde; permissão via `RequestAuthorizationToShare`. O botão "Enviar para Saúde" aparece na sheet do relatório (só onde `IsSupported`). Requer o entitlement `com.apple.developer.healthkit` **ativo no perfil de provisionamento**. O arquivo está em `Pressio.iOS/HealthKitEntitlements.plist.disabled` + `<CodesignEntitlements>` (foi desativado porque o perfil não tinha a capability e o install falhava; **re-ativar = renomear de volta + re-adicionar no csproj + habilitar HealthKit no Xcode/regenerar o perfil**). Atenção: o .NET iOS auto-aplica qualquer arquivo chamado `Entitlements.plist` no diretório, mesmo sem `CodesignEntitlements` — por isso está renomeado.
- **Health Connect (Android):** deixado de lado (a lib `connect-client` 1.1.0.4 usa corrotinas Kotlin `IContinuation` sem wrapper `Task` e crasha em device). `AndroidHealthExportService` está em **stub** (`IsSupported=false`, botão oculto). Package + permissões no manifest + minSdk 26 + launcher de permissão no `MainActivity` já estão no projeto (prontos para retomar).
- **Android (apresentação):** app renomeado para **"Pressio"** (Activity `Label`) e splash de boot usa o ícone do Pressio (`@drawable/icon`), não mais o logo Avalonia (`avalonia_anim`). `minSdk 26` (Android 8+, exigido pela lib Health Connect). **`NuGet.config`** na raiz limpa as fontes herdadas e usa só `nuget.org` (o config global do usuário tem uma fonte quebrada "Siplan Packages" que travava o restore).
- **Lógica extraída p/ teste:** `Pressio/Services/MeasurementFilter.cs` (período/medicação/horário/busca) usado por `ApplyFilters`, e `Pressio/Services/ReminderDueCalculator.cs` (`IsDue`/`DayFlag`) usado por `CheckDueReminders`, para serem testáveis sem UI (padrão do `DashboardCalculator`).

## Blood pressure parsing (`BloodPressureParser`)

- Separators are `/`, space, `x`, `X` (matches `PRD.md`). Normalizes the shorthand `13/8` → `130/80` by multiplying by 10 when the value is `< 30`. Ranges: systolic 50–300, diastolic 30–200. Error/validation messages are user-friendly Portuguese.

## Architecture notes

- ReactiveUI MVVM. Compiled bindings are on by default (`AvaloniaUseCompiledBindingsByDefault=true`), so `x:DataType` / strong-typed bindings are expected in XAML.
- Views are located from viewmodels by naming convention in `ViewLocator.cs` (a `FooViewModel` resolves to a `FooView`). The forms are extracted into dedicated ViewModels/Views (`MeasurementFormViewModel`/`MeasurementFormView`, `PatientFormViewModel`/`PatientFormView`, `SettingsViewModel`/`SettingsView`, `ReminderFormViewModel`/`ReminderFormView`) hosted in `MainView` via `<ContentControl Content="{Binding X}" />`; `MainViewModel` composes them and orchestrates (save/refresh) through events (`SaveRequested`/`CancelRequested`/etc.). The layout scaffolding (modal dialog vs. full-page) stays in `MainView`.
- **Form layout pattern:** each form view is a `Grid RowDefinitions="*,Auto"` = `ScrollViewer` (content, scrollable) + fixed footer bar (action buttons). The hosts in `MainView` keep a **fixed header row** (title + close/back) above the form, so header and footer never scroll away — only the middle content scrolls. Desktop dialogs use `Border MaxHeight` + `Grid RowDefinitions="Auto,*"`; mobile pages use `RowDefinitions="Auto,*"`. **No mobile o teclado cobre o rodapé**, então o rodapé (Cancelar/Salvar) é ocultado (`IsVisible="{Binding !IsMobileLayout}"`) e o botão **Salvar** vai para o **cabeçalho** (a seta Voltar cancela); desktop mantém o rodapé. `IsMobileLayout` é uma propriedade setável em cada form VM (atribuída no construtor do `MainViewModel`). `MeasurementFormView`/`PatientFormView` reset the scroll and auto-focus their primary input **on every open** via a `Shown` event raised by the form VM (`NotifyShown()`, called by `MainViewModel` in the show/edit commands); the View subscribes in `DataContextChanged` and also fires it immediately (because the View is created after the first `Shown` is raised).
- `MainViewModel` is constructed with `isMobileLayout`; desktop shows forms as centered **modal dialogs**, mobile/tablet (<11") shows them as **full-screen pages**. Platform hosts wire this up in `App.OnFrameworkInitializationCompleted()`. `MainViewModel.HandleBack()` closes the topmost overlay/page (used by the Android hardware back button) and returns whether it consumed the event; `MainActivity` intercepts it via `OnBackPressedDispatcher` (the system back in SDK 36 bypasses `Activity.OnBackPressed`).
- **Top bar/usuários:** a barra superior tem um **chip tocável "USUÁRIO ATIVO"** (avatar de iniciais + nome) que abre a **tela de usuários** (`ProfileListViewModel`/`ProfileListView` — diálogo no desktop, página no mobile). Nela ficam a lista de perfis (badge **ATIVO**), `+ Novo usuário`, **Editar**/**Excluir** e **Definir como ativo**. A troca de paciente ativo acontece só nessa tela (não há combo/seletor no topo). Editar/Novo usuário é um **drill-down**: a lista fecha, abre o form e retorna à lista ao salvar/cancelar (`_returnToProfileList`). **Terminologia de UI:** o usuário vê **"usuário"** (modelo continua `Patient` internamente).
- **Fontes no mobile:** `Pressio/Converters/MobileFontSizeConverter` aumenta a fonte **somente no mobile** (público mais velho). É aplicado nos forms via `FontSize="{Binding IsMobileLayout, Converter={StaticResource Mob}, ConverterParameter=base;escala}"` — **textos** usam escala ~**1.8**, **controles** usam ~**1.2**. O desktop mantém o tamanho base (`ConverterParameter` retornado sem escala).
- **Fontes no mobile:** `Pressio/Converters/MobileFontSizeConverter` aumenta a fonte **somente no mobile** (público mais velho). É aplicado nos forms via `FontSize="{Binding IsMobileLayout, Converter={StaticResource Mob}, ConverterParameter=base;escala}"` — **textos** usam escala ~**1.8**, **controles** usam ~**1.2**. O desktop mantém o tamanho base (`ConverterParameter` retornado sem escala).
- **Edge-to-edge no mobile (safe area):** a raiz `MainView` tem `TopLevel.AutoSafeAreaPadding="False"` (o fundo do tema ocupa a tela toda, atrás da barra de status/notch) e um `Border x:Name="Root"` de tela cheia com `Background="{DynamicResource PressioBackgroundBrush}"`; `MainView.axaml.cs` lê `InsetsManager.SafeAreaPadding.Top` e aplica como `Padding` do `Root`, para o **conteúdo** ficar abaixo do notch. **O iOS NÃO suporta `SystemBarColor`** (só Android), então a tela cheia é feita via conteúdo edge-to-edge, não por cor de barra.
- **Gestos no mobile (`MainView.axaml.cs`):** só quando `IsMobileLayout`. **Swipe da borda esquerda → voltar** (chama `MainViewModel.HandleBack()` para fechar o overlay/página mais interno), e **toque na faixa da barra de status (topo) → rola ao topo** os `ScrollViewer` visíveis (ref. `ApplySafeAreaPadding` para a faixa). Disparados por `PointerPressed`/`PointerReleased` com `handledEventsToo:true`.
- The measurement list is a **filtered view**: `_sourceMeasurements` holds the recent readings, `ApplyFilters()` projects them (period / medication / time-of-day / notes search) into `Measurements`, which drives both the history list and the dashboard metrics. Filter changes and any CRUD run through `ReloadMeasurements()` → `ApplyFilters()`. **Ações Editar/Excluir aparecem só no card selecionado** (as ações ficam com `Classes="card-actions"` + Style `ListBoxItem:selected StackPanel.card-actions`; o padrão oculto é uma Style base e **não** atributo local — valor local sobrepõe Style). Os botões alcançam o VM via `Command="{Binding $parent[ListBox].((vm:MainViewModel)DataContext).EditCardMeasurementCommand}"` com `CommandParameter="{Binding}"`. **Nova aferição** abre com padrão **Antes da medicação, Sentado, braço Esquerdo** (no `ShowMeasurementFormCommand`).
- Dashboard analytics are computed from the (filtered) `Measurements` in `RefreshDashboard()`: before/after-medication summaries (`BeforeMedicationSummary`/`AfterMedicationSummary`), `TimeDistribution` (madrugada/manhã/tarde/noite), `ContextCounts` (per factor), and the evolution chart built from `SystolicLine`/`DiastolicLine` (smooth `Geometry` via `ChartPathBuilder`) with per-point value `ChartLabels` (`ChartPointLabel`).
- **Sync ao fechar/pausar:** `MainViewModel.SyncNowFromHost()` (async) é chamado no fechamento da janela (desktop, `App.SyncOnCloseAsync` aguarda antes de sair), no `OnStop` do Android e no `DidEnterBackground` do iOS (melhor esforço — o iOS suspende rápido; o sync periódico de 2 min cobre).
- Theming/resources live in `App.axaml` (brush keys like `PressioPrimaryBrush`) and are toggled at runtime by `App.ApplyAppearance(appearance, primaryColor)` in `App.axaml.cs`. Reuse the `Pressio*` brushes and button classes instead of hardcoding colors in views. View-level converters live in `Pressio/Converters/` (e.g. `ColorMatchConverter`).
